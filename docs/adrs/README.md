# Architecture Decision Records

Short, dated records of decisions that shape the system, in [Nygard format](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions) (Context → Decision → Consequences). One decision per file, numbered. `Accepted` means we're building on it; `Deferred`/`Proposed` means we've parked it deliberately and captured the context so we can pick it up later. `plan.md` remains the source of truth for the design as a whole; ADRs record *why* a specific choice was made.

- [0001 — Knowledge ingestion model](0001-knowledge-ingestion-model.md) — Accepted. How channel conversation becomes attributed memory atoms: end-of-turn extraction over a watermark window, human-only sourcing, supersession.
- [0002 — Memory & interaction scope: thread vs channel](0002-memory-scope-thread-vs-channel.md) — Superseded by 0004. Whether the villager should see/learn at channel scope and whether mention-per-thread is the right interaction model.
- [0003 — Memory substrate: Blob live, git snapshot](0003-memory-substrate-blob-live-git-snapshot.md) — Accepted. Where memory lives: Vercel Blob is the live runtime store (cheap writes, no redeploy), git is the periodically-snapshotted public record; atoms are written by an app-runtime `record_atom` tool (C1), not an in-sandbox script.
- [0004 — Channel-scoped interaction: ingest everything, act only on an explicit mention](0004-channel-scoped-trigger-mention-only.md) — Accepted. Everything said in a village channel is context; the villager acts only on an explicit human `@villager` mention. Preserves the anti-loop guarantee; closes 0002.
